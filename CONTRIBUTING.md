# Участие в проекте

1. Создайте отдельную ветку и используйте команды new:chapter / new:module. Сохраняйте существующие ID, slug и материалы.
2. Напишите MDX, уточните источники и реальную глубину их проверки. Учебная синтетика должна быть подписана; результат модели не выдаётся за доказательство о биологии.
3. Новый вычислительный механизм отделите от UI и проверьте независимыми эталонами. Не копируйте функцию в тест как эталон.
4. Выполните `npm ci` и `npm run check`. Для изменённого интерфейса проверьте широкую и узкую страницу, клавиатуру и reduced motion.
5. В PR опишите конкретное поведение, данные/параметры, численные контроли, ограничения и фактически выполненные проверки. Не отмечайте запланированное как готовое.

Публикация происходит из main после Checks. Изменение программы, исторических ID, публичных slug или общих компонентов требует явного объяснения в PR. Чувствительные данные, токены и пароли в репозиторий не добавляются. Полный процесс описан в docs/AUTHORING.md.
