Как сопоставить две последовательности **целиком**, если между соответствующими буквами возможны пропуски? Нужно выбрать не просто похожий участок, а полное выравнивание, которое максимизирует заданную сумму оценок.

**Вход:** две строки A и B, оценка совпадения, оценка замены и линейный вклад пропуска. **Выход:** лучший score, матрица подзадач и оптимальные выравнивания. Это точная задача для выбранной модели; биологическая история из одного score не следует.

Необходимые знания: индексы и пустой префикс из <a href={withBase('foundations/data/#axes')}>справки о данных</a>, состояния и переходы из <a href={withBase('foundations/algorithm/#states-and-transitions')}>справки об алгоритмах</a>. Общая теория <a href={withBase('theory/dynamic-programming/')}>динамического программирования</a> вынесена на отдельную страницу.

<span id="intuition"></span>

## Интуиция

<Example title="Три совпадения">

Для `ACG / ACG` можно сопоставить одинаковые буквы в трёх колонках. При match = 2 получим $2+2+2=6$. Если одна строка короче, полный ответ всё равно должен учесть каждую букву: появится пропуск. На каждом шаге остаётся три решения — сопоставить две буквы, взять букву только из A или только из B.

</Example>

<Definition title="Допустимое глобальное выравнивание">

Пара строк одинаковой длины над буквами и символом пропуска. Удаление всех пропусков восстанавливает исходные A и B в исходном порядке. Колонка из двух пропусков запрещена. Глобальное выравнивание использует обе исходные строки целиком.

</Definition>

Строки содержат только A, C, G, T; регистр нормализуется, внешние пробелы удаляются. Пустая строка допустима. Внутренние пробелы, N, U и введённые символы пропуска отклоняются, а не исправляются молча. Ограничение — 24 буквы в каждой строке. Вычисление детерминированное; autoplay отсутствует.

<span id="scoring"></span>

## Система оценок

В этой главе совпадение даёт **+2**, замена — **−1**, каждая колонка с пропуском — **−2**. Оценка выравнивания — сумма по колонкам. Для пропуска длины k вклад равен $k g$, где $g$ — неположительная оценка одной колонки с пропуском. Это линейная модель: отдельной стоимости открытия здесь нет.

| Колонка | Пример | Вклад |
| --- | --- | ---: |
| Совпадение | A / A | +2 |
| Замена | A / C | −1 |
| Пропуск | A / − | −2 |

Интерфейс принимает целые match от 0 до 10, mismatch и gap от −10 до 0. Увеличение награды или уменьшение штрафа меняет оптимизационную задачу. После изменения входа прежний результат подписан «Предыдущий расчёт» до повторного запуска.

<span id="recurrence"></span>

## Состояние, границы и рекурсия

Пусть $D[i,j]$ — максимальный score выравнивания префикса A длины i и префикса B длины j. Буквы $a_i$ и $b_j$ нумеруются с единицы; пустой префикс имеет длину ноль.

$$
D[0,0]=0,\qquad D[i,0]=i g,\qquad D[0,j]=j g.
$$

Пустую строку можно сопоставить непустой только через пропуски. Поэтому первая строка и первый столбец накапливают вклад g; они не заполняются нулями без изменения задачи.

<div id="equation-nw"></div>

$$
D[i,j] = \max\left\{
\begin{aligned}
D[i-1,j-1] + s(a_i,b_j),\\
D[i-1,j] + g,\\
D[i,j-1] + g.
\end{aligned}\right.
$$

Здесь $s(x,y)=2$ при равных буквах и $s(x,y)=-1$ иначе. Диагональ сопоставляет две буквы; переход сверху добавляет букву A с пропуском в B; переход слева — пропуск в A с буквой B. Все три предшественника относятся к меньшим префиксам и уже вычислены при построчном обходе.

Например, для D[1,1] на входе `ACG / ACG` кандидаты равны **0 + 2 = 2**, **−2 − 2 = −4**, **−2 − 2 = −4**. Максимум 2 приходит по диагонали. Для `A / AA` в D[1,2] равны диагональный переход и переход слева: оба дают 0. Ничья сохраняется в данных алгоритма.

<Algorithm title="Заполнение и traceback">

1. Инициализируйте D[0,0], первую строку и первый столбец.
2. Для каждой пары i, j посчитайте три кандидата и сохраните максимум.
3. Сохраните **всех** предшественников, достигших максимума.
4. Ответ по score находится в D[n,m], где n и m — длины строк.
5. Начните traceback в D[n,m]. На диагонали запишите обе буквы; сверху — букву A и пропуск; слева — пропуск и букву B. Закончите в D[0,0] и разверните записанные колонки.

</Algorithm>

Почему достаточно максимума? Любое полное выравнивание оканчивается ровно одним из трёх типов колонок. Если предшествующее выравнивание префиксов было хуже оптимального, его можно заменить лучшим, сохранив последнюю колонку. Значит, среди оптимальных предшественников есть путь к оптимальному ответу.

<span id="ties"></span>

## Несколько оптимальных ответов

Для `A / AA` два ответа: `A− / AA` и `−A / AA`. Оба имеют score $2-2=0$. Ни один не получает предпочтения из-за экранного положения. Основной вариант выбирается в порядке **диагональ → вверх → влево**; остальные выбираются в списке.

Число оптимальных путей считается точно целыми BigInt и передаётся строкой, чтобы не терять разряды. Самих выравниваний показывается не более 20: число ответов может быть очень большим. Ограничение списка не меняет optimum или точный счётчик. Для двух пустых строк score равен 0 и существует одно пустое выравнивание.

<span id="mechanism"></span>

## Код и стоимость

```text title="Псевдокод · линейный штраф"
D[0, 0] = 0
D[i, 0] = i * gap
D[0, j] = j * gap
for i = 1 .. length(A):
    for j = 1 .. length(B):
        diagonal = D[i-1, j-1] + substitution(A[i], B[j])
        up       = D[i-1, j] + gap
        left     = D[i, j-1] + gap
        D[i, j]  = max(diagonal, up, left)
        save every predecessor equal to D[i, j]
trace back from D[length(A), length(B)] to D[0, 0]
```

Заполнение матрицы использует $O(nm)$ времени и $O(nm)$ памяти; в вырожденном случае учитываются и граничные строки. Счётчик путей использует целочисленную арифметику. Перечисление ответов имеет отдельную стоимость и ограничено первыми 20. Расчёт отделён от React в `src/algorithms/needleman-wunsch.ts`; изменение цвета, размера экрана и выбранной клетки не пересчитывает score.

<span id="limitations"></span>

## Контрпример и ограничения

<Counterexample title="Оптимальное не означает исторически верное">

Даже точный максимум зависит от оценок и граничных условий. Если длинные фланки не относятся к сопоставляемому участку, глобальный алгоритм всё равно включит их в ответ. Для другого вопроса может требоваться локальное или fitting-выравнивание; это запланированные главы, а не режимы текущего эксперимента.

</Counterexample>

Здесь нет аффинных штрафов, PAM/BLOSUM, неоднозначных букв, структурной информации или модели статистической значимости. Совпадение коротких строк может быть случайным. Число равных оптимумов не является вероятностью каждого из них; произвольный выбор traceback не устанавливает положение реального события.

## Практика

<Exercise title="Предсказать до расчёта">

1. Для пустой A и `AC` в B вручную выпишите первую строку матрицы. Ожидаемый score при gap = −2: **−4**.
2. Для `A / AA` объясните два ответа и score **0**. Какая клетка впервые сохраняет ничью?
3. Измените mismatch на −5 для `A / C`. Будет ли одна замена лучше двух пропусков? Проверьте все варианты.
4. Установите все три оценки в 0. Почему число оптимальных путей вырастает, а score остаётся прежним?

</Exercise>

<details>
<summary>Разбор третьего задания</summary>

Одна замена даёт −5, два пропуска — −4. Поэтому оптимальны `A− / −C` и `−A / C−`. Алгоритм не ошибается: именно такая система оценок предпочитает два пропуска. Это полезный контроль смысла параметров.

</details>
