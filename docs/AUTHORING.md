# Руководство автора

## Обычная глава

```sh
npm run new:chapter -- --module M01 --slug smith-waterman --title "Локальное выравнивание Smith–Waterman"
npm run dev:drafts
```

Редактируется созданный MDX и его frontmatter. Навигацию и карточки вручную не копируют. `id` стабилен и не зависит от имени файла. Публичный URL строится из slug родительского модуля и slug главы: `/modules/pairwise-alignment/smith-waterman/`, с base GitHub Pages перед ним. `order` управляет последовательностью глав. Одна глава не равна целому модулю.

Шаблон включает вопрос, вход/выход, необходимые знания, интуицию, теорию, механизм, эксперимент, контрпример, практику и примечания об источниках. Не оставляйте шаблонный текст перед публикацией. Источники выводятся общим компонентом из frontmatter, а не вторым ручным списком.

Статусы: `planned` — запись программы; `draft` — авторская работа; `review` — материал на проверке; `published` — публичный материал. Production-маршруты создаются только для published. `dev:drafts` дополнительно включает draft/review в локальные маршруты и навигацию. Planned-модули представлены карточками и якорями программы, а не пустыми уроками. Draft/review не включаются в публичные карточки и не дают HTML-страниц; поэтому Pagefind и sitemap их не получают. Исходники черновиков в публичном GitHub видны: status не является средством защиты секретов.

Перед публикацией: проверить источники, завершить текст, контроль и границы модели, убедиться в доступности prerequisite, изменить `status` на `published`, запустить `npm run check`. После merge в `main` Checks и отдельный deploy публикуют статический сайт. Один эксперимент на работающем модуле уже есть; каждая новая глава может использовать его либо иметь собственный.

## Модуль → тема → алгоритмы

Темы задаются только в frontmatter модуля, в `topics`. Пример существующей темы M01:

```yaml
topics:
  - id: M01-T01
    slug: dynamic-programming
    title: От префикса к матрице
    summary: Глобальное, локальное выравнивание и выбор граничных условий.
    status: published
    order: 10
    theory:
      - ref: T-DP
```

У темы собственный стабильный ID. Её адрес выводится из slug модуля и темы: `/modules/pairwise-alignment/topics/dynamic-programming/`. У опубликованной темы должен быть хотя бы один опубликованный алгоритм. Planned-тема показывает название и отметку «Готовится», но не создаёт пустую страницу. Draft/review-темы допускаются только в режиме просмотра черновиков.

Глава ссылается на тему через `topic: M01-T01`. Порядок алгоритмов внутри темы задаётся полем главы `order`; второй список готовых глав вручную не ведётся. Запланированные продолжения в `planned_chapters` получают `topic` той же темы.

```sh
npm run new:chapter -- --module M01 --topic M01-T01 --slug smith-waterman --title "Локальное выравнивание"
```

Если `--topic` опущен, команда выбирает первую тему модуля. Для другой темы передайте её ID явно. Неизвестная тема блокирует создание. Перед первой главой планируемой темы переведите саму тему в `draft`, чтобы её локальная страница могла открываться в режиме черновиков. Старые URL алгоритмов сохранены: тема добавляет навигационный уровень, не меняя адрес существующей главы. Общая теория связывается через `theory` и используется повторно.

## Метаданные и единственный источник каждого свойства

| Обязательные поля модуля | Дополнительные поля модуля |
| --- | --- |
| id, slug, title, branch, role, status, question, summary, feature, prerequisites, methods, sources, release_phase, sort_order | title_en, aliases, tags, related, planned_chapters |

`release_phase/sort_order` обязательны в этой реализации, чтобы новая запись не меняла очередь неявно. Утверждённые роли: core, advanced, adjacent. Ветки определены только в `src/data/branches.ts`; принадлежность определяется только module.branch. У K04 роль core, буква ID роль не задаёт.

| Обязательные поля главы | Дополнительные поля главы |
| --- | --- |
| id, module, slug, title, status, summary, question, order, prerequisites, sources; topic, если у модуля есть темы | related, experiment, estimated_minutes |

`prerequisites` может быть пустым списком. Каждый элемент `{ ref: F-DATA, section: axes }` обозначает обязательное знание. `related` — сравнения/ссылки; взаимные related допустимы. Рефы разрешаются по ID. Для опубликованного материала строгие prerequisite должны быть опубликованы; рекомендация не становится строгой зависимостью.

Заголовок и summary главы находятся только в её frontmatter. Карточка модуля строится только из frontmatter модуля. URL вычисляется из slug; отдельного ручного path нет. Название книги находится только в works.yaml; локальный source хранит work и locator. Маршруты чтения хранят только ID и порядок шагов в routes.yaml. Исторические включения и кандидаты — только в editorial-decisions.yaml. Циклы строгих зависимостей, повторные ID/URL, неизвестные рефы и источники блокируют проверку.

## Формула

```md
Оценка префикса — $D[i,j]$.

$$
D[i,0]=i g
$$
```

KaTeX создаёт HTML и MathML. Расшифруйте символы обычным текстом. Длинная формула прокручивается внутри блока. Для стабильного якоря MDX используйте `<span id="boundary"></span>` на отдельной строке перед заголовком; синтаксис `{#id}` в MDX не используется.

## Изображение и внутренние ссылки

Положите авторское изображение, например `matrix.svg`, в `public/images/`. Изображение должно иметь содержательный alt, при необходимости подпись и происхождение.

```mdx
import { withBase } from '@/lib/url';

<img src={withBase('images/matrix.svg')} alt="Матрица с тремя допустимыми переходами в клетку D[2,3]" width="640" height="360" />

<a href={withBase('theory/dynamic-programming/')}>Общая теория ДП</a>
```

Для неопубликованной темы ссылайтесь на `withBase('program/#M13')`, а не на будущий URL урока. Не вставляйте абсолютный `/images/...` без base.

## Источник

Добавьте работу один раз в `src/data/works.yaml`:

```yaml
- id: MY-PAPER
  title: Точное название
  authors: Имена авторов
  year: 2026
  doi: 10.example/replace-with-real-doi
  url: https://example.org/replace-with-real-source
```

Этот пример — форма записи, не научный источник. В главе:

```yaml
sources:
  - id: mechanism
    work: MY-PAPER
    locator: Раздел 2, формула 3; укажите настоящий локатор
    depth: external
```

Допустимая глубина: explained, example, mentioned, external. Не копируйте номера между изданиями. Упоминание в программе не означает прочтения первоисточника; примечание о требующейся сверке нужно заменить после реальной проверки. Собственные примеры подписывайте как синтетические.

## Интерактив

Для существующего компонента:

```mdx
import NeedlemanWunsch from '@/components/experiments/NeedlemanWunsch';

<NeedlemanWunsch client:load />
```

В frontmatter добавьте `experiment: needleman-wunsch`. Это работает только для совместимой задачи глобального выравнивания. У component, algorithm и input schema единый реестр `src/experiments/registry.ts`.

Новый механизм требует отдельной работы: чистая TypeScript-функция в algorithms → независимые численные контроли → React-представление в components/experiments → запись в registry → MDX. Функция не читает DOM, размер окна и React-state. Отображение не пересчитывает optimum ради картинки. Для длинного процесса добавьте отменяемый Worker после подтверждения необходимости; универсального Worker-движка сейчас нет.

Для тяжёлых примеров данные лежат в `public/examples/vN/`, producer — `scripts/precompute/`. Запустите `npm run precompute:demo`: появятся alignment.json и manifest с версией, командой и SHA-256. Загружайте с base, например `fetch(withBase('examples/v1/alignment.json'))`. Называйте такой режим replay: просмотр trace не является новым расчётом. Изменение научных параметров требует другого artifact или нового предрасчёта.

## Новый модуль

Сначала проверьте: тема уже может быть утверждённой planned-записью. Для M07 редактируют `src/content/modules/m07-mapping-qc.mdx`, ID M36 не выдают повторно.

Для действительно новой темы:

```sh
npm run new:module -- --slug new-method --title "Новый самостоятельный метод" --branch sequences --role advanced
```

На исходной программе команда выберет M36, создаст draft и не опубликует его. Ручной `--id` допустим только для свободного нового номера; все исторические ID зарезервированы. Кандидаты K01/K03/M33/K06 остаются decisions и не получают дублирующую module-запись. Для принятия нового модуля потребуется явное редакторское обновление принятого контракта программы в validate-content.ts: исходные 35 и исторические решения защищены от случайного изменения. Новый draft можно написать, проверить и предварительно просмотреть до такого решения.

## Компоненты оформления

В `src/components/learning/` есть Definition, Example, Algorithm, Counterexample, Exercise, SourceList. У первых пяти опциональный prop `title`. Внутри сохраняется MDX; отделяйте текст пустой строкой от открывающего/закрывающего тега. ExperimentPanel и StepPlayer переиспользуются в React. Общие стили автоматически применяются ко всем новым главам.
