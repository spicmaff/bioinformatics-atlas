# Правила работы с атласом

- Основной редакторский источник — docs/06_site_plan_v2.md. Сохранять 35 утверждённых модулей, их роли/ветки, 4 кандидата и все 43 исторических ID. K04 — core; K02→M08, K05→M28, K07→M26; K08 — F-BIO и кейсы. Следующие исходно свободные ID M36/K09. Не перенумеровывать и не переиспользовать исторические номера.
- Несколько глав принадлежат одному модулю. Frontmatter — единственный источник ID/slug/title/связей/статуса; URL выводится из slug. Общую теорию не дублировать; маршруты чтения используют одни страницы.
- Роль core/advanced/adjacent не равна готовности. Статусы planned/draft/review не создают production-маршруты. Не удалять draft guard и не добавлять черновики в Pagefind/sitemap. Наличие открытого исходника в публичном GitHub не скрывается статусом draft.
- Номера страниц, DOI, издания и прочтение не выдумывать. Сохранять locator/depth; явно отличать источник программы, первоисточник, собственный пример и предрасчёт. Публикуемая глава должна быть содержательно проверена автором.
- Чистые функции — src/algorithms, React — src/components/experiments, регистрация — src/experiments/registry.ts. UI отображает результат функции; layout/цвет/масштаб не меняют вычисление. Новая вычислительная семантика требует независимых численных контролей.
- Для NW сохранять контроль ACG/ACG=6, пустая/AC=−4, A/AA=0 и два оптимума при 2/−1/−2. Сохранять лимиты, обработку алфавита, точный счётчик ничьих, детерминированный traceback и явно ограниченное перечисление.
- Перед завершением: npm ci; npm run check. После изменения UI проверить широкую/узкую реальную страницу, управление клавиатурой, ошибки ввода, stale-result и отсутствие глобальной горизонтальной прокрутки. Не объявлять браузерную проверку без фактического открытия страницы.
- Дизайн уточнён пользователем после v2: тёмный кабинет наблюдений, локальные кириллические IBM Plex, книжная типографика и сдержанные пиксельные акценты (docs/DESIGN.md). Главная — короткая сцена-вход без каталога, численных матриц и сводок. Навигация: модули → темы → упорядоченные алгоритмы. Сохранять видимый фокус, цели 44px и reduced motion. Формулы — KaTeX HTML+MathML. Использовать общие learning-компоненты; править глобальные стили с проверкой существующей главы.
- GitHub Pages — статический build с repository base. Проверять ссылки/якоря/изображения/шрифты/поиск. Не добавлять backend, платные сервисы или подписки без предметной необходимости и отдельного пользовательского разрешения. Токены не записывать в файлы или логи.
- В финальном отчёте разделять реализованное, проверенное и запланированное. Внешний блокер не является причиной оставлять доступную локальную работу незавершённой.

- Визуальные материалы: пользователь запретил сгенерированные арты и произвольные псевдонаучные картинки. Сохранять принятую тёмную типографическую оболочку. Научная графика строится из конкретных данных/проверяемой модели; подписи, оси, легенда, происхождение и ограничения обязательны. Учебные синтетические данные не выдавать за экспериментальные. Для сторонних научных изображений проверять источник и условия использования. Не использовать imagegen для оформления этого проекта.
